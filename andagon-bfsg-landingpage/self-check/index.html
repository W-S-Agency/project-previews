1. Что это

Лид-магнит, встраивается в BFSG-лендинг. Пользователь отвечает на 5 вопросов (пошагово, 1 вопрос на экран) → сразу и бесплатно видит результат-«светофор» → кнопка ведёт к лид-форме (бесплатная первичная консультация). Результат + 5 ответов уходят в payload лида.

Модель взаимодействия — stepper (как в Figma «Section / 2-Minuten-Check», 5 фреймов = Frage 1/5 … 5/5): 1 вопрос на шаг, прогресс «Frage N/5», навигация «← Zurück» / «Weiter →», после Frage 5 — «Mein Ergebnis anzeigen». Слева — фиксированная шапка (eyebrow «2-MINUTEN-CHECK» + H2 + интро), справа — шаг. На мобильном колонки складываются в одну.

Поток: Шаг 1 (F1) → … → Шаг 5 (F5) → «Mein Ergebnis anzeigen» → результат → CTA → лид-форма (#kontakt). «Zurück» сохраняет уже данные ответы; «Zum Start zurück» после результата сбрасывает. Self-Service нет — только Managed Service (D-CLNT-010), фикс-цен в инструменте нет.

2. Встраивание (2 файла + init)

<link rel="stylesheet" href="andagon_self_check.css">
<div id="self-check"></div>
<script src="andagon_self_check.js"></script>
<script>
  AndagonSelfCheck.init("#self-check", {
    ctaHref: "#kontakt",                 // якорь лид-формы
    onComplete: function (data) {
      // data = { result: "red"|"amber"|"green", answers: {q1..q5} }
      var a = document.getElementById("lead-ampel");
      var b = document.getElementById("lead-antworten");
      if (a) a.value = data.result;                 // guard: поля должны быть на странице
      if (b) b.value = JSON.stringify(data.answers);
    }
  });
</script>

Без зависимостей. Тема — через CSS-переменные (andagon: жёлтый #F6D709 только как фон с чёрным текстом). В WordPress — отдельный template-part / блок, JS/CSS через enqueue; инлайн-копию логики не делать — единственный источник это JS. При будущей миграции на Next.js — evaluate переносится 1:1, тексты/пороги в конфиг/CMS.

4. Логика формирования результата (RU)

Реализована в evaluate(answers) (вынесена и экспортирована для тестов). Считаем сверху вниз, первое сработавшее правило выигрывает. По умолчанию всегда 🟡 (жёлтый) — 🟢 никогда «по умолчанию».

Шаг 1 — промежуточные признаки (посчитать первыми)

verbraucherbezug (есть обращение к B2C)  = F1 ∈ {shop, bank, telko, saas}       ИЛИ  F2 ∈ {ja, unsicher}
luecke           (есть пробел)           = F4 ∈ {nein, weiss_nicht}             ИЛИ  F5 ∈ {teilweise, nein, weiss_nicht}
voll_abgesichert (всё закрыто)           = F4 == ja_nachweis                    И    F5 == ja
reine_dl_ohne_vb (чистая B2B-услуга)     = F1 == b2b                            И    F2 == nein
klein            (микропредприятие)      = F3 == klein

Шаг 2 — правила (строго в этом порядке!)

Правило 1 → 🔴 «hoch»    (заголовок: «Sie sollten handeln»)
   ЕСЛИ verbraucherbezug И luecke
   (сюда попадают ВСЕ магазины/шопы с любым пробелом — размер не важен)

Правило 2 → 🟡 «mittel»  (заголовок: «Teilweise abgesichert»)
   ЕСЛИ verbraucherbezug И voll_abgesichert
   (есть B2C-релевантность, но уже всё проверено и технически ок)

Правило 3 → 🟢 «gering»  (заголовок: «Wenig dringend»)
   ЕСЛИ reine_dl_ohne_vb И klein И F4 == ja_nachweis
   (только чистая услуга без продажи товара + микропредприятие + есть подтверждение)

Правило 4 → 🟡 «mittel»  [ПО УМОЛЧАНИЮ]
   во всех остальных случаях
   (в т.ч. B2B без подтверждения, «не уверен», крупные без проверки — безопасный жёлтый, не зелёный)

Как показывается (карточка, §-тексты DE менять нельзя): «Handlungsbedarf: hoch / mittel / gering» — слово окрашено + заголовок + текст + жёлтая CTA. Цвет никогда не единственный носитель смысла (слово hoch/mittel/gering несёт смысл — для доступности).

6. Передача лида (конверсия)

Лид-форма — отдельный блок страницы (#kontakt), не часть виджета. CTA результата ведёт туда (ctaHref). Через onComplete({result, answers}) прокидываем ампел + F1–F5 в payload лида (скрытые поля), чтобы Sales видел контекст.

Отправка лид-формы = конверсия. Форму верстаем мы; поток в тикет-систему (Brevo/sibforms → Ticketsystem → Sales) строит andagon — маппинг полей согласовать с их техникой. Odoo не трогаем. Обязательные поля: Name · E-Mail (geschäftlich) · Unternehmen · Website-URL · DSGVO-чекбокс (без галочки submit заблокирован). Телефон/сообщение — опционально. Добавить ссылку на Datenschutz.

7. Трекинг (после доступов)

События GA4 (имена в CONFIG.events): assessment_start (первый клик), assessment_complete (параметр result = ампел), lead_submit (ключевая конверсия, на лид-форме). Стек GA4 + GTM → импорт в Google Ads.

⚠️ До согласия (Pre-Consent): assessment_start/assessment_complete срабатывают до DSGVO-галочки. Пропускать их только при наличии Analytics-Consent (Consent Mode / условие триггера в GTM) — на BFSG-странице иначе рискованно. Виджет только шлёт в gtag/dataLayer; гейтинг — в GTM/Consent Mode. НЕ переносить инвертированный Consent-Mode главного сайта (D-AUDIT-001). Google-Ads-доступ ещё не получен (GA4 ✅ / GTM ✅) — трекинг включаем, когда будет.

8. Доступность (обязательно — это BFSG-страница)

Виджет уже собран доступным; при встраивании сохранить: полная навигация с клавиатуры (Tab/Enter/Space), видимый фокус (3px); каждый вопрос — fieldset/legend + role="radiogroup", нативные радио; результат в role="region" aria-live="polite" с программным фокусом; при смене шага фокус уходит на «Frage N/5» (объявляется скринридером); ампел не только цветом (слово hoch/mittel/gering + цвет); ошибка как role="alert"; контраст ≥ 4.5:1; жёлтый только с чёрным текстом. В WordPress не оборачивать в page-builder-конструкции, ломающие семантику. См. Dev-Notes дизайнера в Figma + build-todo.md.
